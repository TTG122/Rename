# 06 · 更新怎么推给手机（发版手册）

> 一句话结论：**iOS 上的 App 不能自己下载新版本安装包。** 更新只有三条合法通路——
> 重签覆盖安装、TestFlight、App Store。选哪条取决于你有没有付费开发者账号。

---

## 一、三种通路对比

| | 自签重装 | TestFlight | App Store |
|---|---|---|---|
| 成本 | 0 元 | Apple Developer Program **688 元/年** | 同左 |
| 需要 Mac 吗 | 不需要（GitHub Actions 出包 + Windows 上签名） | 上传要 Mac 或 Actions | 同左 |
| 手机上怎么更新 | 手动重装一次 IPA | **TestFlight 弹通知，点一下就更新** | App Store 自动/手动更新 |
| 有效期 | 免费账号 7 天，付费账号 1 年 | 每个 build 90 天 | 永久 |
| 数据保留 | 保留（同一个 Bundle ID 覆盖安装） | 保留 | 保留 |
| 能带扩展/小组件 | 免费账号不行，付费账号可以 | 可以 | 可以 |
| 适合谁 | 只自己用 | 自己和朋友、小范围内测 | 面向所有人 |

**你现在的情况**：工程里已经配好 `Build IPA` 工作流，没有 Mac 也能出包，所以走第一条最省事；
想省掉“每周重签”，再考虑 688 元的账号。

---

## 二、通路一：自签重装（现在就能用）

### 1. 出包

推到 GitHub → `Actions` → **Build IPA** → `Run workflow` → 跑完在本次运行的 `Artifacts` 里下载
`简记-sideload.ipa`（约 60 MB，未签名）。

### 2. 装到手机

Windows 上用 **Sideloadly**（sideloadly.io），Mac 上用 **AltStore**：

1. iPhone 用数据线连电脑，手机上点「信任」
2. Sideloadly 里选 `简记-sideload.ipa`，Apple ID 填自己的（免费账号即可）
3. 点 `Start`，输入 Apple ID 密码（只在本地用于生成签名，不会上传）
4. 手机上：设置 → 通用 → VPN 与设备管理 → 信任你的 Apple ID → 打开 App

### 3. 更新时要注意的两件事

- **直接覆盖安装**，不要先删 App，删了数据（账本）就没了
- 免费账号的描述文件 **7 天过期**，过期后 App 一打开就闪退，重新做一遍第 2 步就又能用
- 想免去每周重签：装 **SideStore**，配合 WireGuard 在手机上自动续签（一次性配置，之后自动）

---

## 三、通路二：TestFlight（推荐给“想推送到手机上”的人）

这是唯一能做到“手机上收到提示 → 点一下就更新”的免费-ish 方案，也是内部测试的标准做法。

### 一次性准备

1. 买 Apple Developer Program（688 元/年，个人账号即可，审核 1-2 天）
2. App Store Connect → 我的 App → `+` 新建，套装 ID 选 `com.qingdianjizhang.app`
3. Xcode 里三个 target 的 Team 都选这个付费团队，勾上 App Groups / iCloud（见 `docs/02`）

### 每次发版

```bash
# 1. 改版本号：CFBundleShortVersionString 必填递增（1.1.0 → 1.2.0）
#    CFBundleVersion 每次上传都必须比上一次大（4 → 5 → 6…）
# 2. 归档
xcodebuild archive \
  -project QingDianJiZhang.xcodeproj \
  -scheme QingDianJiZhang \
  -archivePath build/简记.xcarchive

# 3. 导出 IPA（ExportOptions.plist 里 method = app-store-connect）
xcodebuild -exportArchive \
  -archivePath build/简记.xcarchive \
  -exportOptionsPlist Config/ExportOptions.plist \
  -exportPath build/

# 4. 上传（或用 Transporter 图形界面拖进去）
xcrun altool --upload-app -f build/简记.ipa -t ios -u 你的AppleID -p 专用密码
```

上传后等 5-15 分钟处理完，App Store Connect → TestFlight：

- **内部测试**（团队账号，最多 100 人）：**不需要审核**，加人后立刻能装
- **外部测试**（邮箱邀请，最多 1 万人）：首版要过一次 Beta 审核（通常 1 天内）
- 测试者手机装 TestFlight App，会收到**推送通知**，点「更新」即升级，数据保留
- 每个 build 有效期 **90 天**，到期前传个新 build 即可续上

## 四、通路三：上架 App Store

TestFlight 跑顺了再上架。流程与审核要点见 `docs/02` 第四节——记账类 App 被拒最常见的原因是
「需要登录才能用」「隐私政策缺失」「截图与实际不符」，这个 App 三条都不涉及，风险不高。

上架后用户端就是普通的 App Store 更新推送，你只需要每次递增版本号、写更新说明。

## 五、为什么不能“App 内自己更新”

iOS 的应用沙盒不允许 App 下载可执行代码并加载运行（App Store 审核指南 2.5.2），
唯一例外是企业证书内部分发（299 美元/年的 Enterprise 账号，且只允许发给本公司员工）。
所以市面上所谓“App 内检查更新”，能做的只有：

1. 读一个版本号（比如 GitHub Release 的 latest 接口）
2. 比本地 `CFBundleShortVersionString` 大就弹个提示
3. 点「去更新」跳到 App Store 或下载页

如果以后想要这个提示，可以加一个 `UpdateChecker`：请求
`https://api.github.com/repos/<你>/<仓库>/releases/latest`，取 `tag_name` 与本地版本比对。
**但不要让它替你装包**——那一步 iOS 一定会拦。

## 六、每次发版的检查清单

- [ ] `Config/App-Info.plist` 的 `CFBundleShortVersionString` 已递增（1.1.0 → 1.2.0）
- [ ] `CFBundleVersion` 比上一次上传的大（4 → 5）
- [ ] 三个 target 的版本号一致（App / Share / Widget）
- [ ] `python tools/verify_parser.py` 全绿（改了识别规则时尤其要跑）
- [ ] 真机跑一遍：双击背面 → 识别 → 落库 → 月报导出
- [ ] 数据迁移没破坏老账本（覆盖安装后旧记录还在）
- [ ] 更新说明写清楚这一版改了什么
